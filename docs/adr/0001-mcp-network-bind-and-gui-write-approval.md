# Retain network-wide MCP bind with per-write GUI approval

The built-in Streamable HTTP MCP server continues to bind `0.0.0.0` without authentication so existing clients on the network keep working. This deliberately exposes read tools to anyone who can reach the port: they may enumerate and exfiltrate data through the active GUI connection, and can flood the local GUI with write approval prompts. Tool descriptions/annotations are warnings, not security controls. A shared main-process, one-pending-at-a-time GUI gate is required for each standalone MCP write, tied to the exact validated input and active client; denial, lost GUI, cancellation, timeout, disconnect/switch, and shutdown fail closed. It does not protect `aggregate` pipelines with `$out` or `$merge` (separate future work), so the bind is not safe to expose to untrusted networks. Users must limit network access themselves; loopback-only binding or authenticated access would break current remote clients and is not introduced by this ticket.
